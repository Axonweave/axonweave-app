# P5-0 - Phase 5 M0: Review Phase 4, reconcile schema, choose and wrap FSRS

## What was built
- `docs/ASSESSMENT_ARCHITECTURE.md`: what Phase 4 already provides, the gaps found, the schema changes, and a table mapping every spec 5.x endpoint to an existing route or a new one (no duplicates).
- Decisions **D-102 to D-114** in `docs/DECISIONS.md` (topic source, attempt and answer schema, FSRS library, where review state lives, scheduler parameters and retention, derived aggregates, idempotency, retention and deletion, timezone, descriptive-grading rules, route mapping, revision sessions). One line per choice in `docs/AUTOPILOT_LOG.md`.
- **Migration 0009** (single head): extends `quiz_attempts` (status `abandoned`, counts, max score, time taken, evaluation status, submit idempotency key), `quiz_attempt_answers` (grading method, max score, evaluation status/detail, AI-assisted flag), `quiz_questions.topic`, `flashcards.topic` and `flashcards (id, user_id)` unique key; adds `flashcard_scheduling`, `flashcard_reviews`, `revision_sessions`, `revision_recommendations` with composite ownership FKs, unique and partial-unique constraints, check constraints and indexes on `user_id`, `due_at` and timestamps. Models in `app/models/revision.py` and the two extended model files.
- **`FsrsScheduler`** (`app/modules/revision/fsrs_scheduler.py`): pure adapter over py-fsrs (state + rating + now in, new state out; no DB, clock or randomness; fuzzing off; configurable target retention 0.70 to 0.99; parameter-set version string). `fsrs==6.3.2` pinned in `backend/requirements.txt`.
- **Topic labels**: `study_quiz` and `study_flashcards` prompts released as version 2 (version 1 kept unchanged); the generator output models accept `topic`; generated rows store it (NULL when empty).
- Not built (by design, later milestones): quiz or revision endpoints, services, UI, analytics.

## Decisions made (with reasons)
- **py-fsrs 6.3.2, MIT**: latest on PyPI (checked 2026-11-12), only dependency `typing-extensions`, FSRS-6 defaults; the spec forbids a hand-made scheduler. Optimizer extras (torch, numpy, pandas) are not installed.
- **`stability`/`difficulty` are double precision, not DECIMAL** (spec 4.3): the library uses floats and rounding would change schedules.
- **No `topic_performance` table**: statistics are derived from attempts and reviews; a stored aggregate only with a measured need and a recalculation job (D-108).
- **Topic via a column plus prompt v2**, not guessed from text; old rows keep NULL.
- **Routes reuse `/study/quizzes/...`**; only the cross-quiz attempt list, abandon, evaluation retry and attempt delete are new for quizzes (D-113).
- **One active revision session per user** (partial unique index) for simple resume semantics.
- Downgrade of 0009 deletes `abandoned` attempts (the old status set cannot hold them; they carry no result) and drops the four new tables, which discards review history by design.
- Test change with reason: `tests/ai/test_ai_schema.py::test_sync_is_idempotent_and_marks_one_default` asserted that every stored prompt is active; with two released versions of a key only the highest is active (D-41), so the test now asserts exactly that.

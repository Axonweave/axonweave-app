# P4-6 - Frontend for generation, library, summaries, flashcards and guides (Phase 4 M6)

Built together with P4-7 on branch `autopilot/p4-5` (the branch already carried M5); see `P4-7.md` for quizzes, export and preferences.

## What was built
- **API client** `frontend/src/lib/api/study.ts` over regenerated OpenAPI types; error codes mapped to plain messages.
- **Study materials page** `/study`: search, type filter, archived toggle, list with duplicate, archive, delete (confirmation), pagination, running-job panel with polling, cancel and failure text. Linked from the sidebar and the Library page.
- **Generate dialog**: source selector (document, subject, chapter, pasted text with a character counter), type, only the settings of the chosen generator, language, usage hint, progress, cancel, failure states. Entry points on subject, chapter and document pages open it with the source fixed. Only touched settings are sent, so saved preferences still apply.
- **Viewers**: summary (sections, bullets, source reference chips, "added explanation" chip, per-section regenerate), study guide, glossary (server search, topic filter, sort), formula sheet (KaTeX, "Not verified" note, flagged formulas, plain-text fallback), question bank (filters, no answers), flashcard deck (study mode with flip, shuffle, progress, arrow keys; edit mode with add, edit, delete, favourite, reorder, regenerate selected with side-by-side preview).
- **Editing and versions**: generic text editor over the stored payload (backend-owned fields locked), save as a new version, conflict message, version history with view and restore, regeneration review (current versus new, apply or discard, stale handling).
- **Backend change (with test)**: `StudyMaterialOut.item_id` (deck or quiz id) so the UI can reach the deck and quiz routes; `test_material_reports_deck_and_quiz_item_ids` (incl. foreign user 404). Decision D-101.
- Safe rendering: model text through the existing sanitised Markdown component; KaTeX `trust:false`; upgraded KaTeX to 0.19.1 after `npm audit` showed an advisory on the first version.

## NOT verified / limitations
- Regeneration preview and apply were not driven in the browser (the fake provider cannot write study output); they are covered in the backend tests and the review component is exercised by type checking only.
- No automated accessibility audit (axe); roles, labels and keyboard use are asserted.
- Library UI filters by type and archived only; subject, chapter and workspace filters exist in the API.
- Whole-material favourites are not built (not in M5).

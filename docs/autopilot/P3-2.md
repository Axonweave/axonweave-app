# P3-2: Documents upload API - replace-file flow and version switch

Most of P3-2 (upload, list/get/rename/delete, download, export, security tests) was already on main. This PR adds the one missing piece, item 4 of the prompt.

## Added
- `POST /api/v1/documents/{id}/replace` (multipart, one file, same file type). Shares `_validate_and_store` with upload (magic bytes, size, zip/image limits, scanner, quota). Stores `v(N+1)`, adds a version row and a queued job, bumps `latest_version`. `active_version` is untouched, so the old version stays active and searchable (D-68).
- 409 `PROCESSING_IN_PROGRESS` while the latest version has a queued or running job. 422 `FILE_TYPE_MISMATCH`. Other users' documents are 404.
- `DocumentRepository.activate_version` also deletes the other versions' chunks in the same transaction.
- Fix found by running the tests: `GET /documents/{id}/download` and `/inline` served the latest version. They now serve the active version (latest only if nothing is processed yet), and Content-Length uses the size of the version actually streamed.
- OpenAPI and `frontend/src/types/api.generated.ts` regenerated.

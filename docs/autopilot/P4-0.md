# P4-0 - Phase 4 M0: common generation engine

## What was built
- `docs/STUDY_GENERATION_ARCHITECTURE.md` (reuse review of Phase 1 to 3, design), decisions **D-78 to D-90**, `docs/AUTOPILOT_LOG.md`, `docs/PHASE4_ENV_PLACEHOLDERS.md`.
- Migration **0004**: `study_materials`, `study_material_versions`, `generation_jobs`, `study_generation_preferences` (composite ownership FKs, partial unique index for duplicate prevention, subject/chapter links cleared on delete, grants). `request_kind='generation'` already existed (0003).
- Engine `backend/app/study/`: request schema and fingerprint, generator registry with validated per-generator settings, `SourceReader` (ordered, sampled, retrieved, ordered batches for map-reduce), context estimate and model selection, versioned prompt entries, Pydantic structured-output validation with exactly one correction call, source-reference stripping.
- Jobs on Celery (`study.run_generation`, `study.dispatch_pending`, `study.sweep_stale_jobs`): all eight statuses, progress, heartbeat, atomic claim, cancellation (also mid provider call), no auto-restart, retries only for transient provider errors, safe error codes.
- Limits and quotas: per-minute, daily jobs, active-job cap, daily token quota, size and time limits; one `ai_usage_records` row per provider attempt (`request_kind=generation`, unknown stays NULL).
- API: `POST/GET /study/generations`, `POST /study/generations/{id}/cancel`, `GET /study/materials/{id}`, `GET /study/generators`. Test-only `echo` generator proves the whole path (refused in production).
- OpenAPI and `frontend/src/types/api.generated.ts` regenerated.

## Decisions made (with reasons)
See D-78 to D-90 and `docs/AUTOPILOT_LOG.md`. Key ones: stale running jobs are failed, never restarted (spec 17.3); a timeout is never retried (may already be billed); generic `/study/generations` route until real generators exist; chunk-collection sources deferred.

# P4-1 - Phase 4 M1: Summary generator (backend only)

## What was built
- `summary` generator (`backend/app/study/generators/summary.py`): six types (quick, detailed, section-wise, exam-oriented, beginner-friendly, key-point), settings per spec 5.3 (detail level, language, examples, definitions, terms, formulas, preserve headings, source references), structured sections per 5.4 with an `additional_explanation` flag (5.5), versioned prompts (`study_summary`, `study_summary_notes`).
- Ordered map-reduce in the engine for chapters that do not fit one prompt (D-91): every batch in reading order is condensed to notes, notes of all batches reach the reducer (condensed further only if needed); a `coverage` report (documents, chunks, batches, complete) is stored with the material and batch counts are in the job's `source_stats`.
- Source references validated like Phase 3 citations: invalid numbers stripped (also in map steps, restricted to the numbers that step saw).
- Thin source (< 20 est. tokens) refused with 422 `GENERATION_SOURCE_TOO_SMALL` before any provider call.
- Editing and versions (D-92): `PATCH /study/materials/{id}` (optimistic `expected_version`, 409 on conflict), `GET .../versions`, `GET .../versions/{n}`, `POST .../restore`. Version 1 is never changed.
- Regenerate whole or one section as a preview: `POST /study/materials/{id}/regenerate` -> job; `GET /study/generations/{id}/preview`, `POST .../preview/apply`, `DELETE .../preview`. Nothing is replaced until applied; a preview older than the current version is 409 `PREVIEW_STALE`, so edits are never overwritten.
- Migration 0005 (`generation_jobs.preview`), OpenAPI types regenerated.

## Decisions made (with reasons)
D-91, D-92 in `docs/DECISIONS.md`; one-liners in `docs/AUTOPILOT_LOG.md`. Notably: section regeneration uses heading retrieval with a sampled fallback; edits are not subject to generation caps; the `regenerate` field is internal (rejected from clients); pasted-text summaries cannot be regenerated (text is not stored).

## NOT verified / limitations
- No real model was called; summary quality (coverage of concepts, faithfulness, clarity, spec 15.5) is untested.
- Map-reduce tested with the FakeProvider and tiny budgets; real token limits and cost of long chapters are untuned.
- Frontend lint/build/Vitest not run (only the generated types file changed). No endpoints per type; the generic `POST /study/generations` with `generation_type: "summary"` is used.
- Condense rounds (notes too large for the reducer) are implemented but not covered by a dedicated test.
- Per-user rate limiting on edit endpoints not added.

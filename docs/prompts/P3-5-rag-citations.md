# P3-5 - Phase 3 M5: RAG and citations
Follow docs/AUTOPILOT.md. Read CLAUDE.md, docs/DECISIONS.md, docs/TASKS_Phase3.md, docs/PHASE3_SPEC.md sections 13, 14, 16, 19.4, 19.5, 21.4 and 22.4, and the Phase 2 orchestration, context manager, SSE and message code. Backend only. Extend the existing AI orchestration; do not build a second chat pipeline.

1. Conversation scope: scope_type (general, workspace, subject, chapter, document) and scope_id, validated by the ScopeResolver; changeable mid-conversation; the scope used is stored on each message. The message request accepts the context object from the spec (scope and answer_mode). A client can never name documents it does not own.
2. RAG as a context provider in the context manager: build the query (follow-up rule from DECISIONS), retrieve, apply the threshold, select chunks within the token budget (diversity, de-duplication), build the RAG prompt as a new prompt-registry version with delimited untrusted reference material, call the existing provider layer.
3. Answer modes: document_only (fixed insufficient-evidence reply, no LLM call, when nothing passes the threshold), document_first (general knowledge allowed but clearly labelled), general (no retrieval).
4. Citations: numbered [n] markers; the backend validates every marker against the retrieved chunks, strips invalid ones and persists message_citations. Streaming sends message.citations before the deltas and message.completed carries the validated final text and citations. Regenerate keeps the scope and re-retrieves.
5. Endpoints GET /citations/{id} and GET /documents/{id}/sources/{chunk_id}, each verifying document access; deleted or inactive sources return unavailable.
6. Usage: retrieval embedding cost and chat cost recorded; quotas still enforced.
7. Tests with the Fake providers: an answer supported by retrieved text; insufficient evidence in each mode; multiple sources; contradictory passages; follow-up retrieval follows the new question; citation validity and rejection of fabricated citations; scope switching; another user's document id as scope returns 404 (spec 22.5 case 4); a document deleted mid-conversation is no longer retrievable; prompt injection inside a document (instructions in document text are not followed and other users' data never reaches the prompt); no document content in logs.
8. Live Gemini check: do NOT run; list under HUMAN-NEEDED with the exact command the human should run.

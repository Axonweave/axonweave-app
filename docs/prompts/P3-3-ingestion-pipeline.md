# P3-3 - Phase 3 M3: Extraction, OCR, normalisation and chunking pipeline
Follow docs/AUTOPILOT.md. Read CLAUDE.md, docs/DECISIONS.md, docs/TASKS_Phase3.md, docs/DOCUMENT_ARCHITECTURE.md and docs/PHASE3_SPEC.md sections 6 to 9, 17 and 22.1 to 22.2. Backend and worker only.

Build the pipeline as separate, individually testable stages run by one idempotent Celery task: validate -> extract -> OCR (only when needed) -> normalise -> structure -> chunk. It then hands off to embedding in the next task; for now a version ends in status "chunked" and never "completed".
1. Extractors: PDF (PyMuPDF: per-page text, reading order from blocks, metadata, block bboxes), PPTX (python-pptx: slide number, title, text frames, bullets, tables, speaker notes), DOCX (python-docx: headings, paragraphs, lists, tables kept as structured rows), TXT, Markdown, images (OCR). Run OCR only on pages with too little digital text; store OCR confidence and warnings; flag low-quality extraction.
2. Normalisation (unicode, whitespace, line breaks, duplicate removal) that preserves code, math symbols and tables. Structure detection from parser data only (heading hierarchy, lists, tables, code); no LLM.
3. Structure-aware chunking: section > paragraph > sentence boundaries; configurable size and overlap (start 500-800 tokens with 75-120 overlap); keep tables, code and definitions intact where possible; stable chunk indexes; full metadata (page or slide, section heading, token count, bboxes, extraction confidence).
4. Job runner: stage-by-stage status updates, retries only for transient errors, timeouts, memory limits, safe error codes (no stack traces to users), cancellation, rerun deletes and rebuilds that version's chunks in one transaction, stale-job sweep.
5. Fixtures generated in code: text PDF, multi-page PDF, image-only (scanned-style) PDF, PPTX with headings/bullets/notes, DOCX with tables and headings, empty file, corrupted file, large file, mixed content. Tests for PHASE3_SPEC 22.1 and 22.2: provenance (page/slide) correct, overlap, token limits, no large content loss (extracted text coverage), no duplicates, a rerun produces identical chunks, a corrupted file ends failed with a safe code.
6. If a `testdata-private/` folder with real documents exists, report extraction and chunking quality (page counts, empty pages, OCR usage, chunk size distribution) in your summary; never print or commit document content. If it does not exist, list this under HUMAN-NEEDED.

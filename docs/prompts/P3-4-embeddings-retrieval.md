# P3-4 - Phase 3 M4: Embeddings and retrieval
Follow docs/AUTOPILOT.md. Read CLAUDE.md, docs/DECISIONS.md, docs/TASKS_Phase3.md, docs/DOCUMENT_ARCHITECTURE.md, docs/PHASE3_SPEC.md sections 10 to 12, 19.3 and 22.3, and the Phase 2 provider and usage code. Backend only.

1. EmbeddingProvider interface (embed_documents in batches, embed_query, dimensions, model id, capabilities), registry, Gemini adapter (check the current embedding API docs before coding; unit-test it with a mocked SDK client, no live calls), FakeEmbeddingProvider (deterministic, test and dev only, refuses production), contract tests like the LLM provider ones. A script that lists available embedding models without printing the key (do not run it against the real API). Record the chosen model, dimension and the "verify live" step in docs; leave the live verification under HUMAN-NEEDED.
2. Embedding stage in the pipeline: batching, rate-limit handling with backoff, no duplicate embeddings on rerun, failed chunks recorded, dimension validation, usage recorded in ai_usage_records with request_kind=embedding. Then the version becomes completed and active in one transaction. Only then is the document searchable.
3. Retrieval service: semantic, keyword (Postgres full-text), hybrid with RRF; scope filters (workspace, subject, folder, chapter, document, completed status, active version only). The user filter is applied inside the SQL query before ranking, never after. Configurable top-k and minimum-evidence threshold. Start with exact filtered search; add an ANN index only if you can measure it with the real filters; otherwise document it as a follow-up.
4. Endpoints POST /search/semantic, /search/hybrid and /search/documents/{id}, with scope validated by the ScopeResolver.
5. Retrieval evaluation harness: a small synthetic corpus with known supporting passages and a question set; a script that reports Recall@K, Precision@K and MRR for semantic, keyword and hybrid (with the Fake embedder these numbers only test plumbing: say so). Commit the synthetic set only. Add a mode that runs against `testdata-private/` with a question file the human writes locally.
6. Tests: isolation (spec 22.5 cases 2, 3, 5 and 6), deleted and inactive versions never returned, filters, exact-term queries are found by keyword search, paraphrases found by semantic search where the fake embedder allows it, embedding failure handling, model or dimension mismatch rejected.
